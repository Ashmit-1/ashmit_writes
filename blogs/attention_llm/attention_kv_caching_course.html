Level 1 · The big picture

Attention is the lookup. KV cache is the notebook.

During autoregressive generation, every new token asks the model to compare its query against the keys and retrieve values from earlier tokens. The KV cache keeps those old keys and values so the model does not recompute them at every decoding step.

Level 1 · Intuition

Why does KV caching exist?

Without a cache

At decoding step t, you could recompute keys and values for the entire prefix 1…t. That repeats work you already did.

Step t: recompute K₁…Kₜ and V₁…Vₜ → attend → emit token t+1
This is correct, but it repeatedly reads and transforms the same history.

With a cache

At step t, the old keys/values are already stored. Compute only the new token’s Q/K/V and append its K/V to the cache.

Step t: compute qₜ, kₜ, vₜ → read cache + kₜ,vₜ → attend → emit
The trade-off is memory: every generated token extends the cache.

Level 2 · Core concepts

The design space: what exactly are we compressing?

Q
QueryThe current token’s request for relevant information. Queries are usually computed fresh at decode.
K
KeyAn address-like representation of each previous token. Attention scores compare Q with K.
V
ValueThe payload retrieved after attention scores decide which earlier tokens matter.
KV
KV cacheStored K and V for previous tokens. It is the state reused across autoregressive decoding steps.
Essential

MHA — Multi-Head Attention

Each query head has its own key and value head.

KV/token ≈ 2 × H × D × L

Largest cache among the head-sharing family for the same H and D.

Essential

MQA — Multi-Query Attention

All query heads share a single K head and a single V head.

KV/token ≈ 2 × 1 × D × L

A large cache reduction, with a quality trade-off reported in the original work and later GQA work.

Essential

GQA — Grouped Query Attention

Query heads are partitioned into groups; each group shares one K/V head.

KV/token ≈ 2 × G × D × L

A middle point between MHA and MQA.

Important separationMHA, MQA, GQA and MLA are attention/cache representation strategies. PagedAttention is primarily a memory-allocation and addressing strategy. Quantization is a numeric representation strategy. These can be combined rather than treated as mutually exclusive choices.
Level 2 → 3 · Evolution

How the KV-cache story evolved

There is no single “replacement chain.” The field has added multiple levers, each attacking a different source of cost.

2017

Transformer / MHA

Multi-head attention becomes the standard self-attention architecture.

2019

MQA

Share K/V across query heads to reduce decode-time memory traffic.

2023

GQA + PagedAttention

Use a middle number of KV heads; manage variable-length caches in blocks.

2024

MLA + 2-bit research

Compress the cached state itself via a latent representation; quantize KV caches to fewer bits.

2025–26

Sparse / long-context systems

Reduce the set of attended tokens and increasingly optimize cache storage, reuse and movement.

2026

DeepSeek V4.1-Flash

Combine cross-layer KV reuse, sparse indexing, FP4 global KV and bounded replay.

Why MQA was not the end

Sharing every K/V across all query heads maximizes cache savings within this family, but the GQA paper reports that MQA can degrade quality. GQA introduces an intermediate number of KV heads to recover quality while keeping much of the memory/bandwidth benefit.

Interpretation, from the GQA authorsGQA was proposed as a compromise point: fewer K/V heads than MHA, more than MQA.

Why MLA is a different idea

MLA does not simply say “use fewer KV heads.” It projects the K/V information into a much smaller latent representation and caches that latent vector (plus a small position-carrying component in DeepSeek-V2).

DeepSeek-V2: KV elements/token ≈ (dᶜ + dᴿ) × L ≈ 4.5 D × L

The DeepSeek-V2 paper gives this as an approximately GQA-like cache size with 2.25 groups, while reporting stronger task performance than its MHA comparison. The paper's exact claim is model- and experiment-specific.

Level 3 · System mechanics

Paged allocation: making the cache fit efficiently

Why contiguous allocation wastes memory

If you reserve one giant contiguous region sized for every request's maximum possible output, much of it can sit unused. Different sequence lengths also create fragmentation.

Logical sequence → [block 0][block 1][block 2]…

With PagedAttention, logical KV blocks map to physical blocks that need not be contiguous. New blocks are allocated as tokens arrive.

The operating-system analogy

Think “virtual memory for KV cache”: a request sees logical pages; the runtime maps them onto whatever physical GPU blocks are available.

What changes? Not the mathematical attention rule. The cache is still the same K/V information; its physical placement is more flexible.
Mini allocator simulation

This is a teaching model: 12 physical blocks, 4 tokens per block. The goal is to see dynamic allocation and why physical blocks do not need to be contiguous.

What to notice: each request grows only when it needs another block. Two logical neighbors can live in distant physical blocks, and a freed block becomes available to other requests.

Level 3 · Numeric compression

Quantized KV caches: store fewer bits

What quantization does

Instead of storing each K/V element in a 16-bit or 8-bit floating format, quantization maps values into a smaller discrete representation and stores extra scale information so the values can be approximately reconstructed.

effective cache ≈ quantized values + scale / metadata overhead

The smaller representation can reduce memory capacity pressure and memory traffic, but accuracy and kernel overhead depend on the method.

KIVI as a research example

The KIVI paper studied the value distributions in KV caches and proposed a tuning-free 2-bit method with asymmetric treatment: per-channel key quantization and per-token value quantization.

Reported resultThe KIVI authors report near-preserved quality in their tested models and substantial memory/throughput changes, but those figures are tied to their experimental setup and should not be generalized to every model or hardware stack.

Level 4–5 · Deep dive

DeepSeek-V4.1-Flash: a multi-lever KV strategy

Current as of September 21, 2026DeepSeek released V4.1-Flash on September 10, 2026. Its technical report describes a 552B-backbone multimodal MoE with up to 1M-token context. The cache design combines cross-layer reuse in CSA2, FP4 global KV, and SWA Bounded Replay; the paper reports 890 bytes/token of global runtime KV and about 1/8 of V4-Flash's persistent KV footprint.

1 · Causal Encoder–Decoder (CED)

The architecture is a 20-layer causal encoder followed by a 20-layer decoder. The decoder's global KV is projected from the final encoder hidden states rather than generated independently from each decoder layer's own hidden state.

Why it matters to cachingIt changes where global decoder KV comes from, helping reduce active compute during prefill to 8B parameters/token and decode activation to 16B parameters/token, according to the report.

2 · CSA2: reuse across layers

CSA2 assigns each attention layer one of three static modes: Full, Reindex, or Reuse. The key cache insight is that several layers can share global main KV and indexer K, and some can reuse already-selected Top-K indices.

Computes main KV and indexer K, then indexes the cache to produce fresh Top-K indices.

3 · FP4 global KV

V4.1-Flash extends quantization-aware training to the main global KV cache. The report selects an E2M1 FP4 representation with one E4M3 scale per 16 channels for the main KV cache. The SWA KV cache remains in FP8 because the paper reports greater sensitivity there.

FP4 → 4-bit main global KV payload + per-group scale

4 · SWA Bounded Replay

Instead of persisting every Sliding-Window Attention KV state to SSD, V4.1-Flash reconstructs missing SWA KV by replaying only the most recent nwin tokens. The paper reports negligible quality impact in its experiments while reducing persistent cache storage.

Important nuanceThe reconstructed state is intentionally approximate. The paper treats the small quality cost as a storage–recomputation trade-off, not as a mathematically exact replay.

Review

The Mental Model

ATTENTION = Q asks a question → K scores where to look → V supplies content

KV cache = persistent working memory for autoregressive decoding. It saves repeated K/V computation, but the price is memory capacity and repeated memory reads.

Compress the content

MHA → GQA/MQA reduces the number of K/V heads. MLA compresses K/V into a latent representation.

Pack the memory

PagedAttention allocates fixed-size blocks on demand and maps logical cache blocks to physical memory blocks.

Use fewer bits

Quantized caches trade numeric precision plus metadata for lower bytes per stored value.

DeepSeek V4.1-Flash in one lineIt combines a new Causal Encoder–Decoder architecture with CSA2 cross-layer/global-KV reuse and sparse index reuse, FP4 main global KV, and SWA Bounded Replay—attacking model representation, cache precision and persistent storage together.

5–10 Things to Remember

1. KV cache is a memory trade. You save repeated K/V computation by storing history.
2. Cache size is roughly linear in context. More tokens mean more stored states.
3. MQA/GQA change KV head sharing. They reduce cache size within the standard head-based representation.
4. MLA changes the representation itself. It caches a compact latent, not full K/V per head.
5. PagedAttention is about allocation. It attacks fragmentation and enables block-level sharing.
6. Quantization is orthogonal. You can reduce bits of whatever representation you store.
7. Runtime and persistent caches are different. HBM pressure and SSD/host pressure need different tactics.
8. V4.1-Flash is a compound design. CSA2 + FP4 + bounded replay are coordinated, not a single “attention trick.”
9. Smaller is not automatically faster. Dequantization, kernels, memory access and interconnects still matter.
10. Always check the counting scope. “Bytes/token” depends on what is counted and the exact cache layout.

Glossary

MHA
Multi-Head Attention: each query head has its own K/V head.
MQA
Multi-Query Attention: all query heads share one K head and one V head.
GQA
Grouped Query Attention: query heads are grouped and each group shares K/V.
MLA
Multi-head Latent Attention: low-rank joint compression of K/V into a cached latent state.
KV cache
Stored keys and values for past tokens, reused during autoregressive decoding.
PagedAttention
A block-based KV cache management scheme inspired by OS virtual-memory paging.
Quantization
Representing values with fewer bits plus enough side information to approximately reconstruct them.
FP4
A 4-bit floating-point representation; V4.1-Flash uses E2M1 for the main global KV payload with grouped scaling.
SWA
Sliding-Window Attention: each layer only keeps a local attention window.
CSA2
Compressed Sparse Attention 2: V4.1-Flash's cross-layer reuse + sparse index strategy.
Prefill
Processing the input/prompt to establish the model state before token-by-token generation.
Decode
The autoregressive phase that generates new tokens one step at a time.
