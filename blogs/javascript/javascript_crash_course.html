HTML Fundamentals

What is HTML?

HTML (HyperText Markup Language) is the standard markup language for creating web pages. It describes the structure of a document using a system of elements — each element is defined by a tag, and elements can have attributes that provide additional information.

Document structure

Every HTML5 document follows the same skeleton. This is one of the most predictable interview questions.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Page Title</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <!-- Visible content goes here -->
  <script src="app.js"></script>
</body>
</html>

Key parts:

  • <!DOCTYPE html> — tells the browser this is HTML5
  • <html lang="en"> — root element; lang helps screen readers and search engines
  • <head> — metadata (not visible on the page)
  • <body> — everything visible
  • <meta name="viewport"> — critical for responsive design on mobile

CSS Fundamentals

What is CSS?

CSS (Cascading Style Sheets) describes how HTML elements should be displayed. It separates presentation from structure, allowing the same HTML to be styled differently for different contexts (screen, print, mobile, dark mode).

Three ways to add CSS

<p style="color: red; font-size: 16px;">Hello</p>

Pros: Quick, specific to one element. Cons: Hard to maintain, no reuse, highest specificity (except !important).

<head>
  <style>
    p { color: red; font-size: 16px; }
  </style>
</head>

Pros: Affects one page, no extra file. Cons: Not shared across pages, mixes content and presentation.

<link rel="stylesheet" href="styles.css">

Pros: Reusable across pages, cached by browser, clean separation. Cons: Extra HTTP request (mitigated by HTTP/2). This is the preferred method.

Selectors and specificity

CSS selectors target elements. When multiple rules apply to the same element, specificity decides which one wins.

Specificity calculation — the three-column system

Specificity is calculated as a tuple (A, B, C):

  • A = number of ID selectors (#header)
  • B = number of class selectors, attribute selectors, and pseudo-classes (.btn, [type="text"], :hover)
  • C = number of type selectors and pseudo-elements (div, ::before)

Inline styles have specificity (1,0,0,0) — a fourth column that beats all selector-based specificity. !important overrides everything except another !important.

Interactive specificity calculator

Specificity: (0, 0, 0)

Counts ID selectors, then class/attribute/pseudo-class selectors, then type/pseudo-element selectors.

The CSS Box Model

Every element in CSS is a rectangular box made of four layers. This is one of the most frequently tested CSS concepts in interviews.

Margin (space outside the border)
Border
Padding
Content
width & height apply here

From outside in: Margin → Border → Padding → Content

Critical distinction — box-sizing:
  • box-sizing: content-box (default) — width only includes content. Total width = width + padding + border.
  • box-sizing: border-box — width includes content + padding + border. This is what most developers set globally: *, *::before, *::after { box-sizing: border-box; }

Interview trap: "An element has width: 200px; padding: 20px; border: 5px solid black;. What is its total rendered width?" With content-box: 200 + 40 + 10 = 250px. With border-box: 200px.

JavaScript Fundamentals

Variables: var, let, and const

This is almost guaranteed to appear in an interview. Know the differences cold.

KeywordScopeHoisted?Reassignable?Redeclarable?
varFunction-scopedYes (initialized as undefined)YesYes
letBlock-scopedYes (but in Temporal Dead Zone)YesNo
constBlock-scopedYes (but in TDZ)NoNo
Temporal Dead Zone (TDZ): let and const declarations are hoisted but not initialized. Accessing them before the declaration line throws a ReferenceError. This is the TDZ. 
console.log(a); // undefined (var is hoisted + initialized)
var a = 5;

console.log(b); // ReferenceError: Cannot access 'b' before initialization
let b = 5;
const is not about immutability of value — it's about immutability of binding. You cannot reassign a const variable, but you can mutate the contents of an object or array it holds: 
const arr = [1, 2, 3];
arr.push(4);       // OK — mutating contents
// arr = [5, 6];   // TypeError — reassigning binding

Operators: == vs ===

The abstract equality operator (==) performs type coercion before comparison. The strict equality operator (===) compares both value and type without coercion.

1 == "1"      // true  — string coerced to number
1 === "1"     // false — different types
null == undefined  // true  — special case
null === undefined // false
0 == false    // true  — boolean coerced to number
0 === false   // false
NaN == NaN    // false — NaN is not equal to anything
[] == false   // true  — [] → "" → 0 → false
Best practice: Always use === and !== unless you have a specific reason to allow type coercion. Interviewers often ask "What's the difference between == and ===?" — your answer should mention type coercion and give an example.

Functions and scope

function greet(name) {
  return "Hello, " + name + "!";
}
console.log(greet("Asha")); // Hello, Asha!

Hoisted completely — can be called before the declaration line.

const greet = function(name) {
  return "Hello, " + name + "!";
};
// greet("Asha") works after this line
// greet("Ravi") before this line throws TypeError

Not hoisted — behaves like a variable assignment.

const greet = (name) => "Hello, " + name + "!";
const add = (a, b) => a + b;
const square = x => x * x;    // parentheses optional for single param
const getObj = () => ({ value: 1 }); // wrap object in ()

Arrow functions do not have their own this — they inherit it from the surrounding scope. They also cannot be used as constructors.

map, filter, reduce — the interview trio

const nums = [1, 2, 3, 4, 5];

// map: transform
const doubled = nums.map(n => n * 2);       // [2, 4, 6, 8, 10]

// filter: select
const evens = nums.filter(n => n % 2 === 0); // [2, 4]

// reduce: aggregate
const sum = nums.reduce((acc, n) => acc + n, 0); // 15

// chaining: evens doubled and summed
const result = nums
  .filter(n => n % 2 === 0)  // [2, 4]
  .map(n => n * 2)           // [4, 8]
  .reduce((a, b) => a + b, 0); // 12
Interview pattern: Interviewer often asks: "Write a function that takes an array of numbers and returns the sum of squares of all even numbers." The answer is the chain above: filter → map → reduce.

DOM Manipulation & Events

What is the DOM?

The Document Object Model (DOM) is a programming interface that represents an HTML document as a tree of objects. JavaScript can read and modify this tree to change what the user sees — without reloading the page.

document
└── html
    ├── head
    │   ├── meta
    │   └── title
    └── body
        ├── header
        │   └── h1
        └── main
            ├── p
            └── ul
                ├── li
                └── li

The DOM mirrors your HTML structure but is a live, mutable object model.

Selecting elements

MethodReturnsExample
getElementById(id)Single element or nulldocument.getElementById("app")
getElementsByClassName(cls)Live HTMLCollectiondocument.getElementsByClassName("btn")
getElementsByTagName(tag)Live HTMLCollectiondocument.getElementsByTagName("li")
querySelector(sel)First match or nulldocument.querySelector(".card > p")

Performance note: getElementById is fastest because IDs are unique. querySelectorAll is the most flexible because it accepts any CSS selector. Prefer querySelector/querySelectorAll for complex selectors.

Modifying content, styles, and attributes

const el = document.querySelector("#title");

// Text content (safe — no HTML parsing)
el.textContent = "New Title";

// HTML content (careful — XSS risk if user input)
el.innerHTML = "<em>New</em> Title";

// Styles (camelCase property names)
el.style.color = "#2563eb";
el.style.fontSize = "24px";

// Classes
el.classList.add("highlight");
el.classList.remove("hidden");
el.classList.toggle("active");
el.classList.contains("active"); // true/false

// Attributes
el.setAttribute("data-id", "42");
el.getAttribute("data-id");
el.removeAttribute("data-id");

Creating and removing elements

// Create
const newLi = document.createElement("li");
newLi.textContent = "New item";

// Add to DOM
const ul = document.querySelector("ul");
ul.appendChild(newLi);            // add at end
ul.insertBefore(newLi, ul.firstChild); // add at start

// Remove
newLi.remove();                   // modern way
// ul.removeChild(newLi);         // older way

// Create multiple at once (performance)
const fragment = document.createDocumentFragment();
for (let i = 0; i < 100; i++) {
  const li = document.createElement("li");
  li.textContent = `Item ${i}`;
  fragment.appendChild(li);
}
ul.appendChild(fragment); // single reflow

Event handling

const btn = document.querySelector("#myBtn");

btn.addEventListener("click", function(event) {
  console.log("Clicked!", event.target);
});

// Named function (can be removed later)
function handleClick(e) { /* ... */ }
btn.addEventListener("click", handleClick);
btn.removeEventListener("click", handleClick);

// Multiple listeners for same event
btn.addEventListener("click", () => console.log("Listener 1"));
btn.addEventListener("click", () => console.log("Listener 2"));
// Both fire, in registration order
document.querySelector("a").addEventListener("click", (e) => {
  e.preventDefault();   // stop default navigation
  console.log(e.target);      // element that triggered the event
  console.log(e.currentTarget); // element the listener is attached to
  console.log(e.type);        // "click"
  console.log(e.key);         // for keyboard events
});
  • e.target — the element that actually triggered the event (could be a child)
  • e.currentTarget — the element the listener is attached to
  • e.preventDefault() — stops the default browser behavior (link navigation, form submission)
  • e.stopPropagation() — stops the event from bubbling to ancestors

Events travel through three phases:

  1. Capturing — from window down to the target
  2. Target — the target element itself
  3. Bubbling — from the target back up to window

By default, listeners fire during the bubbling phase. Pass true as the third argument to addEventListener to listen during capturing.

// Capturing listener
el.addEventListener("click", handler, true);

// Bubbling listener (default)
el.addEventListener("click", handler);
Interview favourite: Given nested elements with click listeners, which fires first? During bubbling: innermost → outermost. During capturing: outermost → innermost.

Common Mistakes & Interview Traps

HTML traps

  • Missing alt on images — not just for SEO; screen readers announce it. An empty alt="" is acceptable for decorative images.
  • Using <div> for everything — use semantic elements. Interviewers notice.
  • Nested forms — not allowed in HTML. A form cannot contain another form.
  • Label not associated with input — always use for matching the input's id.
  • Block element inside inline element — e.g. <div> inside <span> is invalid.

CSS traps

  • Margin collapsing — vertical margins of adjacent block elements collapse into the larger one, not the sum.
  • z-index doesn't work on position: static — it only applies to positioned elements (or flex/grid items).
  • em compounds — nested elements with em font sizes multiply. Use rem to avoid this.
  • Inline elements ignore width and height — set display: inline-block or block if you need dimensions.
  • !important is a code smell — it breaks the cascade and makes debugging harder. Use it only as a last resort.

JavaScript traps

  • typeof null === "object" — historical bug. Use value === null to check for null.
  • NaN !== NaN — use Number.isNaN(value) to test for NaN.
  • Floating point precision — 0.1 + 0.2 !== 0.3 (it's 0.30000000000000004).
  • Array sort is lexicographic by default — [10, 9, 1].sort() gives [1, 10, 9]. Use .sort((a, b) => a - b) for numeric sort.
  • Truthy/falsy surprises — [] and {} are truthy; "", 0, null, undefined, NaN, and false are falsy.
  • Global scope pollution — assigning to an undeclared variable creates a global. Always use let/const.

Misconception check

True or false: "const makes an object immutable — you cannot change its properties."

The Mental Model

Everything on the web is three layers working together:

  1. HTML defines what is on the page — the structure and meaning.
  2. CSS defines how it looks — layout, color, typography, responsiveness.
  3. JavaScript defines what happens — interactivity, DOM manipulation, events.

When a user loads a page: the browser parses HTML into the DOM tree → applies CSS rules based on specificity and the cascade → JavaScript can then read and modify that DOM, listen for events, and update the UI without a page reload.

5–10 Things to Remember

  1. Semantic HTML is not optional — it improves accessibility, SEO, and maintainability. Use <main>, <nav>, <article>, <section> instead of <div> wherever the meaning is clear.
  2. Specificity is (A, B, C) — IDs beat classes, classes beat types. Inline styles beat them all. !important is a last resort.
  3. The box model has four layers — margin, border, padding, content. box-sizing: border-box makes width include padding and border.
  4. Flexbox is 1D, Grid is 2D. Use Flexbox for rows or columns; use Grid when you need both.
  5. let and const are block-scoped; var is function-scoped. Use const by default, let when reassignment is needed, and avoid var in modern code.
  6. Use === not == — strict equality avoids type-coercion surprises like "" == false being true.
  7. map → filter → reduce is the interview pattern for array transformations. None of them mutate the original array.
  8. Events bubble outward by default. Use e.stopPropagation() to stop bubbling and e.preventDefault() to stop default browser behavior.
  9. querySelector / querySelectorAll are the most flexible DOM selection methods because they accept any CSS selector.
  10. Strings are immutable; arrays and objects are reference types. Understanding this explains many unexpected behaviors.
