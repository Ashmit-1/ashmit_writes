1. The Big Picture

Imagine two people in different cities who want to exchange letters. They need a postal system: addresses, sorting centers, delivery rules, and a shared language for writing envelopes. A computer network is exactly that — a system that lets devices exchange data using agreed rules (called protocols) and addressing schemes.

At its core, networking answers one question: how do we get data from point A to point B reliably and efficiently? The answer involves layers. Each layer handles one part of the problem, from the physical cables that carry electrical signals up to the applications you use every day.

The Central Idea

Networking is about layered abstraction. Instead of one giant system doing everything, we split the job into layers. Each layer provides a service to the layer above it and relies on the layer below it. This lets us change one part (e.g., swap Wi-Fi for Ethernet) without redesigning the whole system.

Why It Matters

  • Every application you use — browsers, email, video calls — depends on networking.
  • Most IT interviews test networking fundamentals as a core CS subject.
  • Troubleshooting real-world issues (slow internet, connection failures) requires understanding layers.
  • Security — attacks and defenses happen at different layers.

2.2 Network Topologies

Topology describes how devices are arranged and connected in a network.

How it works: All devices connect to a single central cable (the bus). Data travels along the bus in both directions and is received by all devices, but only the intended recipient processes it.

Pros: Cheap, requires less cable, easy to set up for small networks.

Cons: If the main cable breaks, the entire network fails. Performance degrades with many devices. Difficult to troubleshoot.

Analogy: A single highway with no exits — if it's blocked, everyone is stuck.

How it works: Every device connects to a central hub or switch. All communication goes through this central device.

Pros: If one cable fails, only that device is affected. Easy to add/remove devices. Centralized management.

Cons: If the central hub/switch fails, the entire network goes down. Requires more cable than bus.

Analogy: A classroom where every student talks only through the teacher.

How it works: Devices connect in a closed loop. Data travels in one direction (or both in dual-ring) around the ring, passing through each device.

Pros: Predictable performance, no collisions (with token passing).

Cons: A single break can bring down the whole ring (unless dual-ring). Adding/removing devices disrupts the network.

How it works: Every device connects to every other device (full mesh) or to multiple other devices (partial mesh).

Pros: Extremely reliable — if one link fails, data can take another path. High fault tolerance.

Cons: Very expensive and complex to wire. Number of connections grows as n(n−1)/2.

Analogy: A group of friends where everyone has everyone else's phone number.

Interview trap: Hub vs Switch vs Router

A hub broadcasts to everyone (dumb device, Layer 1). A switch sends data only to the intended device using MAC addresses (smart, Layer 2). A router connects different networks and uses IP addresses (Layer 3). A common misconception is that a switch can connect to the Internet — it cannot; you need a router for that.

Prediction: Why do you think ARP works only in IPv4?

Think about it for a moment before revealing.

ARP relies on broadcast MAC frames (FF:FF:FF:FF:FF:FF) to ask "Who has this IP?" IPv6 eliminated broadcast entirely — it uses multicast instead, via the Neighbor Discovery Protocol (NDP). So ARP simply cannot work in IPv6 because the broadcast mechanism it depends on doesn't exist there.

3.2 Subnetting — Interactive Calculator

Subnetting is dividing a larger network into smaller sub-networks. It improves security, reduces broadcast traffic, and makes efficient use of IP addresses.

How subnetting works — the key insight

An IP address has two parts: a network portion and a host portion. The subnet mask (or CIDR prefix) tells you where the split happens. A /24 mask (255.255.255.0) means the first 24 bits are network, the last 8 bits are host.

Formula: Usable hosts = 2(host bits) − 2. We subtract 2 because the network address (all host bits 0) and broadcast address (all host bits 1) cannot be assigned to devices.

4. TCP vs UDP — Transport Layer

The transport layer is responsible for end-to-end delivery between applications. Two protocols dominate: TCP and UDP. They make fundamentally different trade-offs.

FeatureTCPUDP
ConnectionConnection-oriented (handshake)Connectionless
ReliabilityReliable — retransmits lost dataUnreliable — no retransmission
OrderingPreserves packet orderNo ordering guarantee
Error checkingYes (checksum + ACKs)Checksum only
Header size20–60 bytes8 bytes
SpeedSlower (overhead)Faster (low overhead)
Flow controlYes (sliding window)No
Congestion controlYesNo
Use casesHTTP, email, file transfer, SSHDNS, video streaming, gaming, VoIP

Prediction: You're building a live video call app. TCP or UDP? Why?

Think about what happens if a packet is lost during a live call.

UDP. In a live video call, retransmitting a lost packet is pointless — by the time it arrives, the conversation has moved on. It's better to drop the frame and continue. TCP's reliability and ordering guarantees would actually hurt here by adding latency. This is why real-time applications prefer UDP.

4.1 TCP 3-Way Handshake — Interactive

Before TCP can send data, it must establish a connection. This is done through a three-way handshake: SYN → SYN-ACK → ACK.

TCP Three-Way Handshake
Client
→ SYN (Seq = x) Client: "Can we talk? My sequence starts at x."
← SYN-ACK (Seq = y, Ack = x+1) Server: "Yes! My sequence starts at y. I got your x."
→ ACK (Ack = y+1) Client: "Got it. Connection established."
Server
Step 1: SYN Step 2: SYN-ACK Step 3: ACK
Why three steps, not two? A two-way handshake would leave the server uncertain whether the client received the server's SYN-ACK. The third ACK confirms that both sides have synchronized their sequence numbers and are ready to exchange data.

4.2 Connection Termination (4-Way FIN)

TCP connections are terminated with a four-way handshake using FIN and ACK flags:

  1. Client → FIN: "I'm done sending data."
  2. Server → ACK: "OK, I heard you." (Server can still send data — half-close)
  3. Server → FIN: "I'm done too."
  4. Client → ACK: "Acknowledged." (Client waits 2×MSL before fully closing)

What happens when you type a URL and press Enter?

  1. Browser checks its cache for the IP address.
  2. DNS resolution: Browser asks DNS resolver → root → TLD → authoritative server.
  3. TCP 3-way handshake with the web server (port 80 or 443).
  4. If HTTPS, TLS handshake for encryption.
  5. Browser sends HTTP GET request.
  6. Server responds with HTML, browser parses and requests CSS/JS/images.
  7. Page renders. TCP connection may be closed or kept alive.

5.1 DNS — Domain Name System

DNS translates human-readable domain names (google.com) into IP addresses (142.250.190.46). It's the "phonebook of the Internet."

Recursive: Your device asks a recursive resolver (usually your ISP's DNS) to get the final answer. The resolver does all the work and returns the IP. This is the default for most users.

Iterative: The resolver asks each server in turn — root server → TLD server (.com) → authoritative server — and each one refers it to the next. The resolver builds the answer step by step.

5.2 DHCP — Dynamic Host Configuration Protocol

DHCP automatically assigns IP addresses to devices on a network. It uses the DORA process:

  • Discover — Client broadcasts: "Is there a DHCP server?"
  • Offer — Server responds: "Here's an available IP."
  • Request — Client: "I'll take that one."
  • Acknowledge — Server: "Confirmed. It's yours for [lease time]."

6.2 ARP — Address Resolution Protocol

ARP maps an IP address to a MAC address within a local network (LAN). When a device wants to send data to another device on the same LAN, it knows the destination IP but needs the MAC address to build the Ethernet frame.

How ARP works — step by step

  1. Check the ARP cache for an existing IP→MAC mapping.
  2. If not found, broadcast an ARP Request: "Who has 192.168.1.5?"
  3. The device with that IP replies with a unicast ARP Reply: "I do. My MAC is XX:XX..."
  4. The sender caches this mapping and sends the data.

Common ARP misconceptions (interview traps)

  • ❌ "ARP works across the Internet." → ✅ ARP works only within a LAN. Routers do not forward ARP requests.
  • ❌ "ARP works in IPv6." → ✅ IPv6 uses NDP (Neighbor Discovery Protocol), not ARP.
  • ❌ "ARP Request is unicast." → ✅ ARP Request is broadcast; ARP Reply is unicast.
  • ❌ "ARP cache is permanent." → ✅ Dynamic ARP entries expire after a timeout.

6.3 Ethernet & Switching

Ethernet is the dominant technology for wired LANs. It operates at Layers 1 and 2. A switch learns which devices are on which ports by examining the source MAC address of incoming frames, building a MAC address table. When a frame arrives, the switch looks up the destination MAC and forwards it only to the correct port (or floods if unknown).

7. Network Security Basics

7.1 NAT — Network Address Translation

NAT translates private IP addresses to a public IP address (and vice versa) as packets cross the boundary between a private network and the Internet. This conserves IPv4 addresses and provides a basic security benefit: external hosts cannot initiate connections to internal devices because there's no translation entry for unsolicited inbound traffic.

How NAT works

  • Internal device sends a packet with a private source IP (e.g., 192.168.1.10).
  • NAT router rewrites the source IP to its public IP and records the mapping in a translation table.
  • When the reply comes back, the router looks up the table and forwards it to the correct internal device.

NAT operates at Layer 3 but also modifies Layer 4 headers (ports) for connection tracking.

7.3 VPN — Virtual Private Network

A VPN creates an encrypted tunnel between your device and a VPN server, protecting data in transit from eavesdropping on local networks. It does not provide anonymity — the VPN provider can still see your traffic, and websites can still identify you via cookies and browser fingerprinting.

8. Deeper Understanding — Misconceptions & Nuances

Misconception 1: "The OSI model is what the Internet actually uses."

Reality: The Internet uses the TCP/IP model. OSI is a conceptual framework for teaching and design. Interviewers often ask about OSI to test whether you understand layered networking, not because OSI is deployed.

Misconception 2: "A switch can connect to the Internet."

Reality: A switch operates at Layer 2 and connects devices within the same network. To connect to the Internet (a different network), you need a router (Layer 3).

Misconception 3: "TCP is always better than UDP because it's reliable."

Reality: Reliability comes at the cost of latency and overhead. For real-time applications (video calls, gaming), UDP is better because retransmitting lost packets would cause unacceptable delays. The right choice depends on the application's needs.

Misconception 4: "DHCP assigns permanent IP addresses."

Reality: DHCP assigns leases — temporary addresses that expire after a configurable time. Devices can request renewals. Only manual (static) configuration is permanent.

Misconception 5: "NAT is a complete security solution."

Reality: NAT provides a useful side effect — it blocks unsolicited inbound connections by default. But it is not a firewall. Internal hosts can still initiate outbound connections that could be exploited, and NAT can be bypassed in some scenarios.

10. Key Takeaways

  1. Networking is layered: each layer has a specific job and relies on the one below it.
  2. OSI is a 7-layer conceptual model; TCP/IP is the 4-layer model the Internet actually uses.
  3. IP addresses identify devices logically (Layer 3); MAC addresses identify them physically (Layer 2). ARP bridges the two within a LAN.
  4. TCP is reliable, connection-oriented, and ordered. UDP is fast, connectionless, and unreliable — but lower overhead.
  5. The TCP 3-way handshake (SYN → SYN-ACK → ACK) establishes a connection. Teardown uses FIN/ACK.
  6. Subnetting divides networks using CIDR notation. Usable hosts = 2host bits − 2.
  7. DNS resolves names to IPs; DHCP assigns IPs automatically; NAT conserves public IPs.
  8. Switches forward based on MAC; routers forward based on IP. A hub broadcasts to everyone.
  9. Firewalls filter traffic; IDS detects; IPS blocks; VPNs encrypt tunnels. NAT provides incidental inbound protection.
  10. Always distinguish between conceptual models (OSI) and practical implementations (TCP/IP).

The Mental Model

Think of networking as a postal system with layers of responsibility:

Application You write a letter (HTTP request).
Transport You decide: certified mail with tracking (TCP) or regular postcard (UDP).
Network You write the destination address (IP address).
Data Link The local post office routes it to the correct street (MAC address via ARP).
Physical The mail truck drives on the road (cables, Wi-Fi).

Each layer only knows about its own job. The postal worker doesn't read your letter; the truck driver doesn't decide which city to route to. This separation of concerns is the superpower of layered networking.
