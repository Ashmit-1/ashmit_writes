Understanding

Why Accenture asks you this

Networking questions test whether you understand how data actually moves between two machines — because that same mental model underlies APIs, cloud services, Docker networking, Kubernetes services, VPNs and security, all of which are also in your assessment syllabus. Interviewers rarely want a textbook definition; they want to see you reason about a request end‑to‑end.

Learning objective: by the end you should be able to trace what happens when you type a URL and hit Enter, explain TCP vs UDP with a real trade‑off, subnet an IP address on paper, and defend your answers through 2–5 follow‑up questions.

The one picture to hold in your head

Every network conversation is layers wrapping data, like envelopes inside envelopes. Your browser writes a letter (HTTP request). It's put in an envelope addressed by port number (TCP/UDP). That envelope goes inside another addressed by IP address (routing between networks). That goes inside one last envelope addressed by MAC address (delivery on the local wire). Each layer only reads its own envelope and hands the rest inward.

Analogy, not literal mechanism: real headers are added as fixed-format binary fields (encapsulation), not paper envelopes — but the "each layer only needs its own address" idea is accurate.

Predict before you scroll: if two layers do addressing (IP and MAC), why do we need both instead of just one global address per device?
Reveal

IP addresses are logical and hierarchical — they can change (DHCP, moving networks) and are used for routing across networks. MAC addresses are physical, burned into the NIC, and used only for delivery on one local segment. Routers rewrite the MAC address hop-by-hop but keep the same destination IP address until the packet arrives.

Where this shows up in your resume/projects

If your project used a REST API, hosted something on cloud, ran containers, or used SSH/HTTPS — you already used sockets, TCP, DNS, and TLS. Be ready to say so explicitly; Accenture interviewers like candidates who connect theory to what they actually built.

The Mental Model

Every network exchange = addressing + reliability + translation, stacked in layers.

  • Addressing happens at three levels: MAC (local, physical), IP (global, logical), Port (which app/process on that host).
  • Reliability is a choice, not a given: TCP trades speed for guaranteed, ordered, congestion-aware delivery via handshake + ACKs + windows; UDP skips all of that for speed.
  • Translation services sit around the core path so humans and machines can both work: DNS (name→IP), DHCP (auto-assign IP), ARP (IP→MAC), NAT (private→public IP).
  • Delivery is two different jobs: switching moves frames inside one network using MAC tables; routing moves packets between networks using routing tables and IP.
  • Security/identity wraps this stack: HTTPS = HTTP + TLS for encryption/authentication; VPN/IPsec extends a private network's trust across the public internet.
