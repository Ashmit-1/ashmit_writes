Level 1 — The Big Picture

The Dilemma: Why Autoregressive Generation Hits a Memory Wall

When a Large Language Model (LLM) generates text, it does so one token at a time. To generate token $t_{n+1}$, the model must attend to every preceding token $t_1, t_2, \dots, t_n$.

In vanilla attention, computing what token $t_{n+1}$ should attend to requires calculating an attention score between its Query ($Q_{n+1}$) and the Key ($K_i$) and Value ($V_i$) of every past token. This leaves two fundamental choices:

❌ Path A: Recomputing Every Step

Do not save any past activations. When generating token 1,000, rerun forward passes for tokens 1 through 999.

Computational Complexity: O(N²) FLOPs
Total Forward Passes for N tokens: N(N+1)/2
Unusable for real-time latency.
✅ Path B: Key-Value (KV) Caching

Compute the Keys and Values for each past token once, store them in GPU High Bandwidth Memory (HBM), and reuse them at each generation step.

Computational Complexity: O(N) FLOPs per step
Trade-off: Consumes enormous GPU VRAM memory!
Standard method across all modern LLMs.

Level 2 — Mathematical Anatomy

Deconstructing the KV Cache Formula

In standard Scaled Dot-Product Attention (Vaswani et al., 2017), an input embedding $x_t$ is projected into three distinct vectors:

$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{Q K^T}{\sqrt{d_k}}\right) V$

During decoding, token $t$ only generates a single new Query vector $Q_t$. However, it must be multiplied against the Keys ($K_{1 \dots t}$) and Values ($V_{1 \dots t}$) of all previous tokens across all layers.

The Universal KV Cache Memory Formula

Every LLM engineer must know this equation by heart. It determines inference feasibility.

$\text{Cache Bytes per Token} = 2 \times L \times H_{kv} \times D_h \times P_{\text{bytes}}$
2 Key & Value

Factor of 2 because we must store both one Key vector and one Value vector.

L Layers

Total transformer layers in the model (e.g., 32 for LLaMA-8B, 80 for 70B).

H_kv KV Heads

Number of Key/Value attention heads (Equal to Q in MHA, reduced in GQA/MQA).

D_h Head Dimension

Dimensionality of each attention head (commonly 128).

P_bytes Precision

Bytes per scalar: 2 for FP16/BF16, 1 for FP8, 0.5 for FP4.

Total Context VRAM: $\text{Total Memory} = \text{Batch Size} \times \text{Context Length} \times \text{Cache Bytes per Token}$.

Level 3 — Architectural Evolution

From MHA to Multi-Head Latent Attention (MLA)

As context lengths surged from 2,048 tokens to 128k, 1M, and beyond, standard Multi-Head Attention caused GPU memory to overflow. Researchers engineered a sequence of architectural breakthroughs to shrink $H_{kv}$ and compress cache representations.

Multi-Head Attention (MHA)

Full 1:1 Head Ratio (e.g., 32 Query Heads → 32 Key Heads, 32 Value Heads)

KV Cache: 100% (Baseline Max)

How it works: Each query head attends to its own dedicated key and value head. While expressive, when generating token 100,000 for a 70B model, MHA requires loading gigabytes of memory across every single step just to compute one word!

Multi-Query Attention (MQA)

Shazeer, 2019: All Query Heads Share Exactly ONE Key and Value Head

KV Cache: ~3% to 6% of MHA (Massive Drop)

Trade-off: Cache size is cut by a factor equal to the number of query heads (e.g., $32\times$ reduction). However, forcing all attention heads to look at identical keys often damaged reasoning capacity and retrieval precision in complex domains.

Grouped-Query Attention (GQA)

Ainslie et al., 2023 (Used in LLaMA-2 70B, LLaMA-3, Mistral, Gemma)

KV Cache: ~12.5% to 25% of MHA (Sweet Spot)

The Industry Standard: In LLaMA-3 70B, 64 Query heads are partitioned into 8 groups. Each group of 8 Query heads shares 1 Key head and 1 Value head. This recovers almost 100% of MHA's benchmark accuracy while cutting KV cache bandwidth by 8×.

Multi-Head Latent Attention (MLA)

DeepSeek-V2 / V3: Low-Rank Joint Compression + Decoupled RoPE

KV Cache: ~1.5% to 3% of MHA

1. KV Joint Low-Rank Compression:

$c_t^{KV} = W^{DKV} h_t \quad (\text{Compressed latent vector of dimension } d_c = 512)$

2. Decoupled RoPE Key Strategy:

$k_t^R = \text{RoPE}(W^{KR} h_t) \quad (\text{Rotary embeddings applied strictly to a tiny } d_R = 64 \text{ vector})$

3. What is Actually Stored in the KV Cache:

$\text{KV Cache}_t = [c_t^{KV}, \; k_t^R] \quad \text{Total size: } 512 + 64 = 576 \text{ scalars per token!}$

The DeepSeek MLA Innovation: Instead of storing independent Keys and Values for all 128 attention heads, DeepSeek compresses both Keys and Values together into a single latent code $c_t^{KV}$ (512 dimensions). During generation, query projection matrices absorb the up-projection matrix: $W^{UK} \cdot W^{UQ}$, enabling the model to compute attention directly against the compressed latent code!

Memory Allocation & Quantization

PagedAttention (vLLM) & Quantized Caches

PagedAttention (Kwon et al., 2023)

Prior to vLLM, systems allocated contiguous memory based on the maximum possible sequence length (e.g., 4k or 32k tokens). Because generation lengths are unknown beforehand, up to 60% to 80% of VRAM was wasted due to:

  • Internal Fragmentation: Reserved memory for future tokens that are never generated.
  • External Fragmentation: Gaps between differently-sized requests.

The Solution: PagedAttention mirrors OS virtual memory. KV caches are split into fixed-size physical blocks (e.g., 16 tokens). Tokens are appended non-contiguously via a dynamic Page Table.

Quantized Caches: FP16 → FP8 → FP4

Precision directly scales cache footprint. Halving precision doubles max batch capacity:

FP16 / BF16 (Baseline) 2.0 Bytes / scalar
FP8 (E4M3 / E5M2) 1.0 Byte / scalar (2× reduction)
FP4 (E2M1 - DeepSeek-V4.1) 0.5 Byte / scalar (4× reduction)

FP4 requires micro-scaling factors (e.g., FP8 scale per 16 channels) to maintain accuracy during long-context needle-in-a-haystack tasks.

Level 4 — DeepSeek-V4.1-Flash Deep Dive Released Sept 2026

The 890-Byte Breakthrough: How DeepSeek-V4.1-Flash Slashes Cache by 437×

In September 2026, DeepSeek introduced DeepSeek-V4.1-Flash, a 552-billion parameter Mixture-of-Experts model designed specifically to run 1-million-token context windows at production scale without demanding hundreds of GPUs per user stream.

While LLaMA-style MHA models require up to 389,120 bytes per token and DeepSeek-V3 requires 48,068 bytes, V4.1-Flash compresses the KV cache down to an unprecedented 890 bytes per token.

1

Causal Encoder-Decoder (CED)

Rather than an all-layer decoder-only architecture, V4.1-Flash partitions computation into a 20-layer Causal Encoder (8B active parameters) and a 20-layer Decoder (16B active parameters).

Encoder processes prefill → produces 1 final global state → Decoder layers perform Cross-Attention against this shared state once, rather than storing 40 separate KV cache layers.
2

Compressed Sparse Attention 2 (CSA2)

Replaces dense attention with a 3-mode sparse indexing mechanism across layers:

  • Full Mode: Anchors full cache update (Layers 0, 7, 14, 19).
  • Reindex Mode: Scores top-K sparse candidates from a 16,384 position pool.
  • Reuse Mode: Directly inherits routing indices from previous layers, bypassing QK matching!
3

Native FP4 Micro-Scaled Storage

KV cache tensors are stored natively in E2M1 floating point (0.5 bytes per parameter) with micro-block scaling: an FP8 (E4M3) scale is computed across every 16 channels.

Trained end-to-end with Quantization-Aware Training (QAT) to eliminate precision loss during long needle recall.
4

SWA Bounded Replay (No SSD Thrashing)

Instead of offloading massive historical KV states to slow NVMe SSDs or persistent CPU RAM, V4.1-Flash dynamically recomputes intermediate states over bounded sliding windows ($n_{win} = 4,096$ tokens) during context hops.

Preserves ultra-fast decode response time without I/O blocking over PCIe.

Common Misconceptions: Fact vs. Myth

Misconception 1

"The KV Cache speeds up the prompt prefill phase."

False: During prefill, all prompt tokens are processed simultaneously in parallel. The KV cache is written to during prefill, not read from to speed it up. The speedup only occurs during sequential autoregressive decode!
Misconception 2

"PagedAttention compresses or quantizes Key-Value data."

False: PagedAttention is purely a virtual memory management algorithm. It changes where tensor blocks reside in physical RAM (non-contiguous 16-token pages) but does not alter numbers, compress embeddings, or lose a single bit of precision.
Misconception 3

"MLA reduces attention accuracy compared to standard MHA."

False: Empirical evaluations on DeepSeek-V2 and V3 demonstrate that MLA matches or exceeds MHA with identical head count. Because the up-projection is absorbed into the Query matrix at inference, full head expressivity is preserved while drastically lowering cache bandwidth.

🧠 The Mental Model

The 3-Dimensional Axis of KV Cache Optimization

Whenever you evaluate any LLM serving architecture, reconstruct it across these three distinct axes:

1. Head Axis (Dimension Reduction)

Reduce redundant key heads. Move from MHA (1:1) → GQA (8:1) → MLA (joint low-rank compression).

2. Precision Axis (Quantization)

Shrink bytes per scalar without degrading needle recall. Move from FP16 (2B) → FP8 (1B) → Native FP4 (0.5B with micro-scales).

3. Spatial & Temporal Sparsity

Avoid allocating or attending to unnecessary positions. Use PagedAttention to kill fragmentation and CSA2 to reuse index masks.

8 Key Takeaways to Remember

  1. Autoregressive generation is memory-bound: Generating a single token requires streaming gigabytes of past KV tensors through the GPU memory bus.
  2. KV cache formula: $\text{Bytes} = 2 \times L \times H_{kv} \times D_h \times P_{\text{bytes}}$ per token.
  3. GQA is today's default: Grouping 8 query heads to 1 KV head captures near-MHA accuracy with an $8\times$ cache reduction.
  4. PagedAttention fixes waste: Paging eliminates internal memory fragmentation, boosting batch throughput by $2\times$ to $4\times$.
  5. MLA compresses representations: DeepSeek compresses Key and Value matrices into a joint 512-dim latent space and decouples RoPE.
  6. DeepSeek-V4.1-Flash achieves 890 B/token: A 437× reduction over classic MHA unlocked by Causal Encoder-Decoder (CED) cross-projection.
  7. CSA2 operates in 3 layer modes: Full, Reindex, and Reuse modes drastically reduce sparse attention computation.
  8. Native FP4 with micro-scaling: Halves FP8 memory while QAT preserves needle-in-a-haystack accuracy across 1M tokens.

Technical Glossary

Prefill vs Decode Prefill processes input prompts concurrently (compute-bound). Decode generates tokens one-by-one (memory-bound).
Arithmetic Intensity The ratio of floating point operations (FLOPs) to memory bytes transferred from VRAM.
RoPE (Rotary Position Embedding) Encodes relative token distances by rotating query and key vectors in complex 2D planes.
E2M1 FP4 4-bit floating point format with 1 sign bit, 2 exponent bits, and 1 mantissa bit.
